# Per-worker Jev HTTP connection reuse trial

Hypothesis: reuse HTTP connections to reduce setup latency, without deleting any valid model call or changing reader/price policy. Installed httpx._api.request opens/closes a Client per top-level post. Baseline A preserves that exact call; B supplies a worker-local Client.post. Each worker clears response cookies before every request, retaining baseline empty-cookie semantics. No response/result cache, retries, model/body/Authorization/0.7-second timeout/confidence/FAIR/warranty/price guard changes. Failed requests still return JEV_DOWN through the same classifier catch. Thread-local clients avoid cookie races; atexit closes registered clients only at shutdown. Fixed runtime env/proxy configuration is assumed; no env/key rotation is authorized.

Default off, isolated MARKET_DIR/jev_transport with inherited bounded config seller_concession_trial.json. Full task UUID, kind/open-price-band/5-minute paired strata, cap200/100B, durable controls and new-only flags. Existing historical reader/opening trial tasks are excluded. Initial quote/metadata/pricing do not change. Invalid assignment fails A; contaminated task uses baseline. ITT assignments remain sticky, but transport treatment does not. At the callback's logical dispatch selection, B requires a valid finite config with the same id, start <= now < end, no stop and no disabled marker. Missing/malformed/nonfinite config fails A, including an adopted marker without a finite matching config. Other OpeningCue policies are unchanged. Build new configs with JevTransport.trial_config(id, start, end, seed); it rejects nonfinite timestamps and windows outside (0, 1800] seconds and never writes or extends an epoch.

Each seller turn creates fresh lazy transport observation state even when Jev is disabled or no request is needed. A and B both pass through the same callback. Turn events retain immutable ITT arm/id and report effective_arm=A/B, no-dispatch (zero callbacks), or mixed (multiple dispatch arms), plus dispatches containing only selected arm, timestamp and gate reason. Selection is recorded before invoking pool.post/httpx.post, even if the request raises. Event-time OFF/re-ON never rewrites past selection. Old closures hold only their old turn state, so late completions cannot fill another turn. Quote and terminal events have exposure_scope=itt-only, effective_arm=null and dispatches=[]: they are not a copy of the last turn's exposure. No request or response body, URL or credential is added to these observations.

Logical dispatch is the choice of callback before pool/client preparation, not physical socket transmission. OFF during subsequent client preparation does not cancel or reroute the already selected request; the next selection sees OFF. These records do not prove successful network delivery, connection reuse, or settlement.

A/B for fixed30min then individual600s ITT including no replies. API judgments can differ across real calls even if requests are identical; compare safeguards and economic results.
