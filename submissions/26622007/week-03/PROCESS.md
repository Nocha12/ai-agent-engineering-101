# 작업 과정

## 2026-09-15: 설계 초안과 작업 정의

- 사용자가 3주차 README를 기준으로 OpenRouter + DeepSeek 4.1 구현을 요청했다.
- 앞선 대화의 관리자 1명·독립 입찰자 3명, 작업마다 새 대화, 실행별 상태 초기화 설계를 적용한다.
- 사용자가 게임형 과제를 원하지 않아 신제품 출시 준비 업무를 합성 데이터로 구성했다.
- Codex가 작업·역할·코드를 작성하며 사용자의 검토와 결과 해석이 남아 있음을 명시한다.
- tasks.json과 gold를 모델 실행 전에 먼저 커밋한다.
- 현재 프로젝트 .env의 키는 존재하지만 OpenRouter 키 형식이 아니어서 다른 서비스로 전송하지 않는다.
- 실제 API 결과와 모의 응답을 구분한다. 테스트 응답으로 results.csv나 실험 로그를 채우지 않는다.
- AGENTS.md의 사용자 PR 확인 규칙은 로컬에 유지한다. 이번 작업에서 PR을 만들지 않는다.

## 첫 구현과 모의 검증

- 역할·입찰 처리, OpenRouter 전송, 실행기·기록기를 각각 별도 커밋했다.
- 외부 패키지 없이 Python 표준 라이브러리로 구현했다.
- 첫 16개 모의 테스트에서 잘못된 gold 타입과 매우 큰 confidence 값이 정상적인 검증 오류 대신 예외를 내는 문제가 발견됐다.
- 실패 출력을 diagnostics/01-unittest-initial.log에 보존하고 테스트와 함께 먼저 커밋했다.
- gold 타입 검사와 confidence 범위 검사 순서를 수정했다. HTTP 오류 응답도 명시적으로 닫아 리소스 경고를 해소했다.
